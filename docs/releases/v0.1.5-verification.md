# Rail Builder v0.1.5 release verification

Release target: Minecraft **1.21.11**, addon **0.1.5**. The maintainer reported
successful manual acceptance testing of this binary before release preparation.
The release cleanup changes documentation, verification automation and repository
contents, not production code or dependency requirements relative to that tested
candidate. No generated JAR is committed.

The clean release worktree build is **byte-for-byte identical** to the preserved,
manually tested candidate, not merely equivalent class contents. ZIP integrity,
filename, embedded Fabric version `1.21.11-0.1.5`, and dependency requirements
were verified. It contains 21 production class entries, both modules, diagnostics
and the inventory policy/adapter; no verification/probe classes or nested
Meteor/Baritone/NetherPathfinder dependencies are packaged.

Builds used Java 21.0.13, Loom 1.14.10 through the unchanged snapshot coordinate,
Loader 0.18.2, Meteor build 86 and the existing Baritone snapshot on Linux x86_64.
The earlier four-combination production startup matrix remains applicable because
the bytes are identical; see [DependencyCompatibility.md](../DependencyCompatibility.md).
Expected offline Realms authentication warnings were nonfatal. No fresh-cache
resolution or full gameplay matrix was repeated during cleanup.

Routine CI automatically tests the Python verification helpers and runs a clean
Java 21 Gradle build on pushes and pull requests. It fails on build/packaging
errors and uploads the distributable. It has read-only repository permissions
and does not publish. Snapshot publication remains a separate manual workflow,
with write permission only on its publishing job. No CI run was dispatched and
no release/tag/push was performed during preparation.

The maintainer's manual acceptance is distinct from the automated startup and
focused inventory tests. Every gameplay path across every dependency combination
has not been independently revalidated. Other Minecraft versions remain unsupported.
